# Task monitoring executable allowlist

Preset exact executable paths /usr/lib/xorg/Xorg and /usr/bin/Xorg as ignored_task_executables in global settings (editable, empty list explicitly disables matching). This is a task monitoring exclusion, not UID exclusion or a guessed ML framework classifier. GPU device usage stays unchanged. Match exact native executable path (collector psutil exe); argv/command exact absolute first token may support legacy stored records/test/demo data when no native exe exists. No substring, basename, regex, glob, or symlink filesystem reads from web requests.

Persist missing setting keys without overwriting configured lists. Validate strict list of strings, at most50, absolute normalized paths at most4096 chars, reject NUL/newline/relative/glob paths. Root configure validates independently. UI uses existing tags control and shows Chinese/English explanatory text and professional tooltip; settings save sends only editable fields.

Ignored processes cannot seed GPU tasks, become confirmed task targets, trigger deadlines/residual reminders, or receive TERM/KILL. Apply filtering to previously discovered records too without deleting audit or task policy records. Hide wholly ignored task records from task API/list/detail/overview counts; retain recorded metadata for reversal/reconciliation. Do not hide legitimate same-user training processes, misleading command arguments containing Xorg, or other executable paths named Xorg. Removing an entry allows observation again. Account monitoring and full GPU device memory/utilization metrics remain intact.

Scope preview/execute/queued signal guards recheck current allowlist, and native dispatch excludes current native executable paths even when a process execs between collection and signaling. Existing tokens must not authorize newly ignored processes. No process is terminated just because a whitelist rule changes; production native mutations remain false.
