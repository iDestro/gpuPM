整体需求可以定义为：**一个部署在 Ubuntu GPU 服务器上的 Web 管理工具，供管理员统一查看和管理所有用户的 GPU 任务，设置三级业务优先级、存活期限，处理异常和残留进程，并管理服务器本地 Linux 用户、系统用户组及隔离的个人目录。**

用户继续通过 SSH、nohup、训练脚本等原有方式运行程序，无需统一提交到调度平台。

### 1. GPU 任务查看

自动扫描服务器上使用 GPU 的进程，并展示：

| 信息类别 | 展示内容 |
|---|---|
| GPU | 编号、型号、显存使用、利用率 |
| 用户 | 用户名、所属管理组 |
| 进程 | PID、命令、启动时间、已运行时间、状态 |
| 任务关系 | 父子进程树、关联的 GPU worker |
| 管理信息 | 备注、三级优先级、到期时间、保护状态 |

支持按 GPU、用户组、用户、状态筛选，以及按优先级、运行时间和显存占用排序。

**同一训练任务可能包含多个 GPU 进程，应支持将它们作为一个任务管理。**自动识别结果允许管理员确认或调整，不应将整个 SSH 会话中的程序都归为一个任务。

### 2. 三级业务优先级

优先级比较顺序为：

**用户组优先级 > 用户优先级 > GPU 程序／任务优先级。**

每层采用 `0～100`，数值越大越重要。严格按三级顺序比较，不做加权求和。

| 层级 | 配置内容 |
|---|---|
| 用户组 | 组名、成员、组优先级、备注 |
| 用户 | 用户优先级、所属管理组、备注 |
| GPU 任务 | 任务优先级、任务名称、备注 |

每个用户指定一个管理组，用于优先级计算；管理组可独立于 Linux 系统附属组。修改组或用户配置后，对现有任务立即生效。

第一版将优先级用于**展示排序和清理候选排序**，不改变 Linux nice 或 GPU 内核调度。后续可增加资源紧张时自动清理低优先级任务。

### 3. 存活时间管理

管理员可以为任务设置：

- 最大运行时长，例如从启动起最多运行 24 小时；
- 指定到期时间；
- 不限时，以及延期或取消期限。

网页展示已运行时间、剩余时间和超时状态。到期支持“仅提醒”或“自动终止”两种动作。

**高优先级不自动豁免期限。**保护任务到期后仍标记超时，但不自动终止。

后台重启后保留配置，并重新检查任务身份和到期状态。

### 4. 进程与任务终止

支持结束单个进程或整个任务。执行流程为：

1. 核验进程身份和终止范围；
2. 发送 `SIGTERM`，给予正常退出时间；
3. 超时仍未退出时发送 `SIGKILL`；
4. 检查残留进程，记录结果。

手动整组终止前展示受影响的进程。任务识别和清理应考虑不直接使用 GPU 的辅助子进程，例如 DataLoader。

使用 **PID + 启动时间**识别进程，避免 PID 复用导致误杀。默认不向上终止用户的 shell、SSH 会话或无关任务。

### 5. 异常与“僵尸”处理

不同情况分别识别和处理：

| 类型 | 判断与处理 |
|---|---|
| 真正僵尸进程，状态为 `Z` | 展示父进程并告警；不能直接杀掉，需要父进程回收 |
| 主程序退出后的残留 worker | 展示关联依据，支持手动清理；明确归属后可自动清理 |
| 进程存活但疑似卡住 | 根据持续异常信号标记，不能仅凭 GPU 利用率低就自动终止 |
| 到期任务 | 按期限策略提醒或终止 |

对 GPU 任务关联的父子进程一并检查状态，因为真正僵尸可能已不在 GPU 活跃进程列表中。第一版不默认自动终止僵尸的父进程，也不自动重置 GPU。

### 6. Web 管理与操作记录

第一版提供以下页面：

| 页面 | 主要操作 |
|---|---|
| 总览 | 查看 GPU 状态、运行任务、超时和异常数量 |
| 任务列表与详情 | 筛选、查看进程树、设置优先级和期限、终止任务 |
| 用户组管理 | 分别管理业务优先级组与 Linux 系统用户组，维护成员 |
| 用户管理 | Linux 用户增删改查、软删除恢复、停用启用、有效期、密码/公钥、登录历史、主目录/数据目录与配额、业务优先级 |
| 存储与共享 | 查看个人/共享用量和空闲空间、容量告警，配置用户配额及共享项目只读/读写权限 |
| 策略配置 | 扫描周期、退出等待、默认期限、密码策略与容量阈值；查看初始化目录根、配额/ACL 支持状态 |
| 操作日志 | 查看配置修改、手动终止、自动终止及失败原因 |

第一版仅提供管理员登录。记录操作人、时间、目标进程身份、修改前后值、终止原因及执行结果。

### 7. 服务器用户、系统用户组与目录管理

管理员通过页面管理服务器本地 Linux 普通账号，支持查询、新建、修改和删除；已有系统账号默认只读展示，现有普通账号需明确纳管后才能修改。root、系统服务账号、gpuPM 服务账号及维护用 SSH 账号受到保护。

| 功能 | 第一版要求 |
|---|---|
| 新建用户 | 唯一用户名、说明、登录配置、业务管理组；默认 shell 为 `/bin/bash`，默认建立同名私有主组，不授予 sudo/docker 等高权限组 |
| 查询用户 | UID/GID、主组与附属组、shell、正常/停用/到期/软删除状态、有效期、主目录、数据目录、存储用量/配额、纳管状态、进程与登录记录 |
| 修改用户 | 说明、允许的 shell、系统组成员、登录配置、业务组与优先级；用户名和受管个人目录更改只能在目标用户无进程/会话/已知后台活动时，经预览和暂停新登录后执行（离线指用户空闲，可由 Web 发起），禁止带活动迁移和任意 UID/GID 修改 |
| 删除用户（软删除） | 标记已删除并停用新登录，保留 Linux 账号、UID/GID、组关系、配置和全部文件；不移动目录、不终止已有进程/会话；支持查询已删除用户和恢复 |
| 系统组 | 创建、查询、修改普通组和成员、删除无主组引用且无成员的受管组；主组与附属组分别管理，敏感组禁止通过本工具赋权 |
| 停用/启用 | 临时停用独立于软删除，阻止新密码和公钥登录；启用不能覆盖账号到期、软删除或外部限制 |
| 账号有效期 | 设置/延期/取消账号有效期，到期禁止新登录并告警，与 GPU 任务期限独立 |
| 密码策略 | 创建/重置后可要求首次登录改密（默认开启）、密码质量校验与状态展示；不默认强制定期换密码 |
| 存储管理 | 用户目录用量、文件系统剩余空间、容量/inode 告警；受支持文件系统上的用户软/硬配额、宽限期与生效状态 |
| 登录记录 | SSH 成功/失败、来源 IP、方式、公钥指纹（日志可用时）、当前会话与最后成功登录；显示日志覆盖范围 |
| 共享目录 | 独立团队数据目录，配置系统组的只读/读写访问与继承权限，不开放私人主目录或数据目录 |

Linux 系统组负责文件访问等系统权限；业务管理组负责 GPU 的三级优先级。两者独立，不因加入系统组就自动改变业务优先级，也不因业务组调整就修改系统权限。

软件初始化必须明确主目录根路径和数据目录根路径，例如：

```text
主目录根：/home
数据目录根：/data（必须确认实际挂载/存储位置）

/home/alice          /data/alice
/home/bob            /data/bob
```

- 用户目录拥有者为对应 UID 和主 GID，默认权限 `0700`，默认 shell 初始化 umask 为 `077`；alice 默认不能读取、列出、修改或遍历 bob 的私人目录。root 等具有系统权限的管理员除外。
- 主目录放个人配置及软件，数据目录放数据集、模型和训练输出；提供 `~/data` 链接和登录环境中的 `DATA_DIR` 入口，但不强制训练脚本写入该目录。
- 根目录由 root 管理。初始化验证绝对路径、目录边界、权限、容量和预期挂载，禁止重叠/软链接逃逸；预期数据卷未挂载时拒绝创建，不默默落到系统盘。
- 不自动迁移已有用户的数据、不自动更改已有主目录权限；纳管时报告差异，由管理员执行明确的受管目录操作。
- 用户删除只进行软删除，不调用 `userdel`，全部文件保留在原位置，属主与权限不变，用户名和 UID 继续占用。已删除用户默认不出现在正常账号列表，但其运行任务仍照常展示和管理；支持筛选已删除用户、恢复同一账号和原配置，不提供永久删除。
- 软删除须阻止后续密码与公钥登录，并记录停用是否生效；不能只标记数据库或只锁密码。已建立的会话和进程不自动结束，原任务期限与保护策略继续生效；需要结束任务时另走任务终止流程。
- 创建、修改、删除和失败均记录审计。系统账号操作由宿主机权限服务执行；分步骤持久化执行状态，失败后重试不得产生重复账号或误删已有目录。
- 新账号同时支持 SSH 公钥和密码；页面提供初始密码、密码重置与公钥维护，凭据与 Web 管理员凭据独立。部署时检查 SSH/PAM 配置并实测两种登录，不保存明文密码、不盲目放宽全机 SSH 策略。

### 8. 账号生命周期、存储与共享的补充要求

- 停用、软删除、账号到期分别保留原因和时间。展示优先级为软删除、停用、到期、正常，但详情展示所有有效限制；任一限制存在都不能新登录。恢复软删除只撤销软删除原因，启用只撤销临时停用，不绕过期限或外部限制。
- 账号到期按系统支持的日期粒度配置，界面展示 Asia/Shanghai 下的实际生效时间；禁止新登录不自动结束已有训练、会话、定时任务或用户服务。页面列出可发现的活动及扫描覆盖，明确“停用但仍有活动”。结束 GPU 任务仍走独立终止流程。
- 密码创建/重置默认要求首次登录修改，管理员可按账号配置。PAM 下公钥登录也可能受密码过期状态影响，须测试交互 SSH、非交互 SSH/SFTP 并在页面提示改密前限制。平台创建/重置采用密码质量校验；用户自行 passwd 改密的强制策略须经宿主机 PAM 验证，不能把网页校验宣称为全机强制规则。
- 数据目录为 `/data/<用户名>` 形式，初始化指定实际根路径。目录用量统计与按 UID/文件系统的配额用量分别展示，不能混为同一数值。后台统计带采样时间，不跟随链接、不跨越未授权挂载、不在每次 GPU 扫描全量遍历目录。
- 第一版支持本地 ext4/XFS 的用户配额管理，配置空间/inode 软限额、硬限额、宽限期，先探测文件系统、工具、挂载与配额是否已启用，设置后读回核验。未支持/未启用时仍显示用量，但禁用配额提交并说明启用步骤；软件不自动格式化、重挂载或重启生产数据卷。配额降低至当前用量以下先展示写入影响，不清理文件。
- 个人目录用量、配额用量及文件系统空闲空间配置告警阈值，默认 80% 提醒、90% 严重；第一版提醒为页面和事件日志，不自动删文件或终止训练。软删除账号仍计入存储用量，保留配额；恢复账号不清零统计。
- 登录日志采集支持日志轮转、重启恢复、去重、时间/IP/用户名/结果筛选；未知用户名失败记录不错误关联到现有账号。只展示可确认的事实，缺失历史显示“无覆盖”，不推断没有登录；不收集密码或私钥。
- 共享目录示例为 `/data/shared/<项目名>`，其中 `shared` 为受管根保留名称，不能用作新用户名。root 拥有目录，普通用户通过独立系统组获得只读或读写权限，使用 setgid/default ACL 配置允许范围内的新文件继承。用户个人目录继续保持默认 0700。
- 共享授权/撤销、目录权限变更均需预览和审计；不移动或自动删除已有文件。移除组成员不撤销旧进程已持有的组身份或打开的文件句柄，页面提示重新登录及残留访问风险；不自动结束会话。已有文件权限迁移是单独的、明确范围的操作，不默认递归修改目录外文件。

### 9. 第一版范围

**第一版必须实现：**全用户 GPU 进程扫描、任务与父子关系展示、三级优先级、备注、存活期限、超时提醒与自动终止、手动整组终止、僵尸和残留标记、管理员登录与日志，以及服务器本地用户增删改查、系统用户组管理、默认 bash 和隔离的主目录/数据目录，账号停用/启用与有效期、密码策略、存储用量和受支持的配额、登录历史、团队共享目录。

**后续再实现：**资源紧张时按优先级自动清理、卡死自动判断、多服务器统一管理、用户自助申请延期。

技术上采用 **FastAPI + SQLite + NVML + psutil + React 前端**即可。采集和执行服务部署在宿主机，具备查看和管理所有用户进程的权限；网页通过后台接口执行管理操作。
