# Residual process reminders and manual cleanup

User-approved behavior: running → finalizing → awaiting_cleanup → cleaning → finished. Normal worker exit can go directly from finalizing or awaiting_cleanup to finished. No automatic signal is allowed for residual cleanup, including tasks with legacy cleanup_orphans=true or deadline_action=terminate after finalizing.

A confirmed task enters finalizing when its original observed leader identities are absent but confirmed task members remain. CPU postprocessing and GPU workers still running are never automatically killed. Persist finalizing_since on first observed leader disappearance, retain it across refresh/restart, clear it if the leader returns, and clear on finish. The reminder enters awaiting_cleanup only after the configurable waiting period, enabled reminders, all members no longer reporting GPU presence, complete/fresh collection, and eligible unprotected personnel ownership. Protected/other tasks may show finalizing but never actionable awaiting_cleanup.

Introduce task orphan_reminder (default true) and orphan_wait_seconds (default 300, strict integer 1–86400); corresponding settings default_orphan_reminder and default_orphan_wait_seconds. Existing task fields gain missing reminder/wait values without changing names, priorities, protections, runtime or expiry. New templates copy these values. Deprecated cleanup_orphans/default_cleanup_orphans remain API-compatible, disappear from editable UI, and cannot authorize automatic cleanup. They may retain old values in persisted data; legacy automatic branches are removed.

Persisted state is derived only from confirmed memberships; unknown processes remain excluded. Failed collection must not start or advance finalization/reminders. Cleaning means an accepted residual-cleanup operation is queued/running; completion with survivors returns to awaiting_cleanup/finalizing; all exits become finished. Recover interrupted jobs safely after restart.

Reuse preview/terminate operations: POST termination-preview accepts residual_only=true. Agent requires waiting reached, reminders enabled, current human ownership, unprotected task, fresh complete evidence, leader absent and no GPU members. Preview includes exact eligible process identities, commands/runtime and exclusions. It binds residual intent to the existing single-use scoped token. Execute and each native signal revalidate residual conditions, task revision, current membership/UID/protection and PID identity; changed conditions reject or skip rather than widening targets. Residual intent permits explicitly confirmed reparented members; ordinary termination keeps existing exclusions. Confirmation/reason remains required, jobs use existing TERM/grace/KILL/idempotency/audit paths.

UI: display all live tasks by default (running, finalizing, awaiting_cleanup, cleaning), retain explicit status filters including each new state. List and detail show reminder/wait timing, a clear awaiting-cleanup notice, and “Terminate residual processes” action only for eligible tasks; existing preview confirmation provides exact process list before execution. Task/global forms expose reminder switch and waiting duration via existing h/m/s input. Chinese/English and professional tooltips remain unified. No email/other external notifications: reminder is in overview/task list/detail.

Validation: frozen-clock process sequence tests, natural exits before/after wait, reset/restart, GPU resume and incomplete sampling, nonhuman/protected guards, legacy auto-cleanup disabled, deadline terminate unable to kill finalizing workers, residual preview/execute/queued identity races, ordinary termination unchanged, API validation and defaults migrations. Component tests plus demo Chrome E2E for default active visibility, states, reminder editing, exact scoped preview/manual completion. No real production GPU termination during deployment.
