## 部署与验收项，不应误报为完全没有代码

- 目录：当前 API 配置 home_base=/var/lib/gpupm-qa/home，data_base=/var/lib/gpupm-qa/data，share_base=/var/lib/gpupm-qa/data/shared。新建 gpu_trial 一致；已有 /home 账号不一致。正式根目录与数据卷安排尚未完成。调整根目录前必须处理已有受管账号兼容，不能直接换路径宣称完成。
- 配额：实机只读查询当前发现 /（ext4），quota_supported=true、quota_enabled=false。已有 ext4/XFS 原生隔离文件系统验收记录，但当前实际卷尚不可提交配额；不应自动重挂载或格式化。
- ACL：当前实例 capabilities.acl.status=tools_present_unverified。历史独立原生共享验收通过，不等于当前实例已验证生产共享授权。
- SSH/PAM：已有真实密码/公钥登录、停用和到期验收；检查到的原生登录脚本使用 require_password_change=false，未发现覆盖首次改密下交互 SSH、非交互 SSH、SFTP 的完整矩阵。新 gpu_trial 尚未由本轮完成首次登录。
- 稳定性：历史报告明确未做整机重启、长期负载、完整升级回滚恢复演练及多卡/MIG/MPS/容器全部组合。本轮未重跑这些测试。最近一次后端修复实测 270 项通过不是这些验收的替代。
- 文档：PRD 仍列指定到期时间，但用户已选择仅保留最大运行时间；部分历史部署段落仍写只读，最新记录已明确开启。需要统一现行功能说明与历史记录。

## 不作为首版遗漏追补

- 残留 worker 自动清理：用户已明确选择等待后人工确认。
- 独立指定任务到期时间：用户已明确删除，改为最大运行时间自动推算。
- 永久删除用户及文件：明确禁止。
- 维护账号训练管理拆分：用户已决定维护账号默认不用于 GPU 训练。
- 多服务器、自助申请延期、资源紧张自动清理、通用卡死自动判断：PRD 后续范围。
- 邮件/聊天推送、多级 Web RBAC：当前没有必须实现的需求；首版为管理员入口、页面与事件日志提醒。

## 建议顺序

先修正变更预览与创建失败恢复，再补接管预检、可写/保护说明、生命周期与诊断展示；最后完成正式目录和配额/ACL/SSH 部署验收。不要为填满功能清单扩展调度器或多服务器系统。
