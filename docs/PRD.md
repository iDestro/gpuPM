整体需求可以定义为：**一个部署在 Ubuntu GPU 服务器上的 Web 管理工具，供管理员统一查看和管理所有用户的 GPU 任务，设置用户组任务策略、存活期限，处理异常和残留进程，并管理服务器本地 Linux 用户、系统用户组及隔离的个人目录。**

用户继续通过 SSH、nohup、训练脚本等原有方式运行程序，无需统一提交到调度平台。

### 1. GPU 任务查看

自动扫描服务器上使用 GPU 的进程，并展示：

| 信息类别 | 展示内容 |
|---|---|
| GPU | 编号、型号、显存使用、利用率 |
| 用户 | 用户名、所属管理组 |
| 进程 | PID、命令、启动时间、已运行时间、状态 |
| 任务关系 | 父子进程树、关联的 GPU worker |
| 管理信息 | 备注、有效优先级及配置来源、最大运行时间、推算结束时间、保护状态 |

支持按 GPU、用户组、用户、状态筛选，以及按优先级、运行时间和显存占用排序。

**同一训练任务可能包含多个 GPU 进程，应支持将它们作为一个任务管理。**自动识别结果允许管理员确认或调整，不应将整个 SSH 会话中的程序都归为一个任务。

### 2. 用户组与任务策略继承（2026-10-16 更新）

管理员统一配置任务策略；每个用户选择一个用户组。共享目录的读写授权独立管理，不通过任务用户组赋权。

| 类型 | 配置与继承规则 |
|---|---|
| 默认组（内置） | 直接继承策略配置，新账号默认进入该组 |
| 普通用户组 | 每一项可以继承全局配置，或单独覆盖 |
| 自定义组（内置分类） | 每位用户使用自己的个人配置，未覆盖项继承全局；该组没有共同配置 |

可配置项：任务优先级（0～100）、最大运行时间、任务保护、到期动作、残留提醒及等待时间。缺失字段表示继承；显式“不限时”是独立覆盖值。个人配置初始全部继承，切换分组后保留，只有进入自定义组才生效；普通组配置与个人配置互斥。

新任务采用单一有效优先级，数值越大越重要；明确的任务单独编辑优先于纳入管理时解析的用户组/个人策略。所有任务保存策略快照和来源，修改策略配置、用户组或用户分组只影响后续新任务。现有任务需要在任务详情明确编辑；不能通过组配置绕过维护账号等保护。

默认组与自定义组不可删除或改名；删除普通组需确认成员迁入默认组，个人配置保留。旧用户优先级和旧组优先级有迁移审计；历史任务保留原排序快照，页面解释迁移保留的三级排序。

用户组页统一展示组策略和成员；账号详情管理分组与个人配置；删除独立“用户业务策略”入口。原生系统组功能位于账号详情的高级系统组管理，仍按原权限规则执行，不与任务组同名创建或同步。优先级仅用于平台展示和排序，不改变系统 nice 或 GPU 内核调度。

详细设计与迁移边界见 [用户组策略设计](superpowers/specs/2026-10-16-user-task-groups.md)。

### 3. 存活时间管理

管理员可以为任务设置：

- 最大运行时长，例如从启动起最多运行 24 小时；
- 根据启动时间和最大运行时间自动推算预计结束时间，只读展示；
- 不限时，以及延期或取消期限。

网页展示已运行时间、剩余时间和超时状态。到期支持“仅提醒”或“自动终止”两种动作。

**高优先级不自动豁免期限。**保护任务到期后仍标记超时，但不自动终止。

后台重启后保留配置，并重新检查任务身份和到期状态。

### 4. 进程与任务终止

支持结束单个进程或整个任务。执行流程为：

1. 核验进程身份和终止范围；
2. 发送 `SIGTERM`，给予正常退出时间；
3. 超时仍未退出时发送 `SIGKILL`；
4. 检查残留进程，记录结果。

手动整组终止前展示受影响的进程。任务识别和清理应考虑不直接使用 GPU 的辅助子进程，例如 DataLoader。

使用 **PID + 启动时间**识别进程，避免 PID 复用导致误杀。默认不向上终止用户的 shell、SSH 会话或无关任务。

### 5. 异常与“僵尸”处理

不同情况分别识别和处理：

| 类型 | 判断与处理 |
|---|---|
| 真正僵尸进程，状态为 `Z` | 展示父进程并告警；不能直接杀掉，需要父进程回收 |
| 主程序退出后的残留 worker | 主进程退出后标记收尾中；默认等待5分钟、确认无GPU占用后提醒管理员，预览确认后手动终止，不自动清理 |
| 进程存活但疑似卡住 | 根据持续异常信号标记，不能仅凭 GPU 利用率低就自动终止 |
| 到期任务 | 按期限策略提醒或终止 |

对 GPU 任务关联的父子进程一并检查状态，因为真正僵尸可能已不在 GPU 活跃进程列表中。第一版不默认自动终止僵尸的父进程，也不自动重置 GPU。

### 6. Web 管理与操作记录

第一版提供以下页面：

| 页面 | 主要操作 |
|---|---|
| 总览 | 查看 GPU 状态、运行任务、超时和异常数量 |
| 任务列表与详情 | 筛选、查看进程树、设置优先级和期限、终止任务 |
| 用户组管理 | 统一配置任务策略、继承与组成员；系统权限组位于账号高级功能 |
| 用户管理 | Linux 用户增删改查、软删除恢复、停用启用、有效期、密码/公钥、登录历史、主目录/数据目录、业务优先级 |
| 存储与共享 | 查看个人/共享用量和空闲空间、容量告警，配置共享项目只读/读写权限 |
| 策略配置 | 扫描周期、退出等待、默认期限、密码策略与容量阈值；查看初始化目录根、ACL 支持状态 |
| 操作日志 | 查看配置修改、手动终止、自动终止及失败原因 |

第一版仅提供管理员登录。记录操作人、时间、目标进程身份、修改前后值、终止原因及执行结果。

### 7. 服务器用户、Linux 权限组与目录管理

管理员通过页面管理服务器本地 Linux 普通账号，支持查询、新建、修改和删除；已有系统账号默认只读展示，现有普通账号需明确纳管后才能修改。root、系统服务账号、gpuPM 服务账号及维护用 SSH 账号受到保护。

| 功能 | 第一版要求 |
|---|---|
| 新建用户 | 唯一用户名、说明、登录配置；任务策略默认进入默认组；默认 shell 为 `/bin/bash`，默认建立同名私有主组，不授予 sudo/docker 等高权限组 |
| 查询用户 | UID/GID、主组与附属组、shell、正常/停用/到期/软删除状态、有效期、主目录、数据目录、存储用量、纳管状态、进程与登录记录 |
| 修改用户 | 说明、允许的 shell、系统组成员、登录配置；账号详情独立配置任务用户组与个人策略；用户名和受管个人目录更改只能在目标用户无进程/会话/已知后台活动时，经预览和暂停新登录后执行（离线指用户空闲，可由 Web 发起），禁止带活动迁移和任意 UID/GID 修改 |
| 删除用户（软删除） | 标记已删除并停用新登录，保留 Linux 账号、UID/GID、组关系、配置和全部文件；不移动目录、不终止已有进程/会话；支持查询已删除用户和恢复 |
| Linux 权限组 | 默认展示平台创建或明确启用管理的普通项目权限组；其他组只读查询，符合人员范围的已有普通项目组可经预览启用管理。用户私有主组在账号详情展示，human 为只读人员分类组。仅可删除没有附属成员、主组用户及共享目录引用的受管权限组；系统/敏感组禁止授权和修改 |
| 停用/启用 | 临时停用独立于软删除，阻止新密码和公钥登录；启用不能覆盖账号到期、软删除或外部限制 |
| 账号有效期 | 设置/延期/取消账号有效期，到期禁止新登录并告警，与 GPU 任务期限独立 |
| 密码策略 | 创建/重置后可要求首次登录改密（默认开启）、密码质量校验与状态展示；不默认强制定期换密码 |
| 存储管理 | 用户目录用量、文件系统剩余空间、容量/inode 告警；不设置用户磁盘限额 |
| 登录记录 | SSH 成功/失败、来源 IP、方式、公钥指纹（日志可用时）、当前会话与最后成功登录；显示日志覆盖范围 |
| 共享目录 | 独立团队数据目录，配置系统组的只读/读写访问与继承权限，不开放私人主目录或数据目录 |

原生系统组负责系统权限；用户组负责 GPU 任务属性继承；共享目录通过用户读写列表独立授权。任务用户组的调整不修改系统组或共享 ACL。

账号附属组和共享目录授权只允许新选择受管普通权限组；账号自己的私有主组及旧有授权可保持，编辑其他信息不得意外清除已有组关系。更换主组后原私有组仍保留私有属性，恢复自己的私有主组需核对原 GID 及当前人员成员范围。旧共享授权仅改备注时保留原 ACL；更换任一授权组时，最终双方都须为受管权限组。启用已有组的管理只保存管理记录，不修改 Linux 成员或 GID；包含未启用管理账号的组在这些账号启用管理前仍只读。组分类结合真实主组引用和管理记录，不仅依据组名或 GID 猜测。

软件初始化必须明确主目录根路径和数据目录根路径，例如：

```text
主目录根：/home
数据目录根：/data（必须确认实际挂载/存储位置）

/home/alice          /data/alice
/home/bob            /data/bob
```

- 用户目录拥有者为对应 UID 和主 GID，默认权限 `0700`，默认 shell 初始化 umask 为 `077`；alice 默认不能读取、列出、修改或遍历 bob 的私人目录。root 等具有系统权限的管理员除外。
- 主目录放个人配置及软件，数据目录放数据集、模型和训练输出；提供 `~/data` 链接和登录环境中的 `DATA_DIR` 入口，但不强制训练脚本写入该目录。
- 根目录由 root 管理。初始化验证绝对路径、目录边界、权限、容量和预期挂载，禁止重叠/软链接逃逸；预期数据卷未挂载时拒绝创建，不默默落到系统盘。
- 不自动迁移已有用户的数据、不自动更改已有主目录权限；纳管时报告差异，由管理员执行明确的受管目录操作。
- 用户删除只进行软删除，不调用 `userdel`，全部文件保留在原位置，属主与权限不变，用户名和 UID 继续占用。已删除用户默认不出现在正常账号列表，但其运行任务仍照常展示和管理；支持筛选已删除用户、恢复同一账号和原配置，不提供永久删除。
- 软删除须阻止后续密码与公钥登录，并记录停用是否生效；不能只标记数据库或只锁密码。已建立的会话和进程不自动结束，原任务期限与保护策略继续生效；需要结束任务时另走任务终止流程。
- 创建、修改、删除和失败均记录审计。系统账号操作由宿主机权限服务执行；分步骤持久化执行状态，失败后重试不得产生重复账号或误删已有目录。
- 新账号同时支持 SSH 公钥和密码；页面提供初始密码、密码重置与公钥维护，凭据与 Web 管理员凭据独立。部署时检查 SSH/PAM 配置并实测两种登录，不保存明文密码、不盲目放宽全机 SSH 策略。

### 8. 账号生命周期、存储与共享的补充要求

- 停用、软删除、账号到期分别保留原因和时间。展示优先级为软删除、停用、到期、正常，但详情展示所有有效限制；任一限制存在都不能新登录。恢复软删除只撤销软删除原因，启用只撤销临时停用，不绕过期限或外部限制。
- 账号到期按系统支持的日期粒度配置，界面展示 Asia/Shanghai 下的实际生效时间；禁止新登录不自动结束已有训练、会话、定时任务或用户服务。页面列出可发现的活动及扫描覆盖，明确“停用但仍有活动”。结束 GPU 任务仍走独立终止流程。
- 密码创建/重置默认要求首次登录修改，管理员可按账号配置。PAM 下公钥登录也可能受密码过期状态影响，须测试交互 SSH、非交互 SSH/SFTP 并在页面提示改密前限制。平台创建/重置采用密码质量校验；用户自行 passwd 改密的强制策略须经宿主机 PAM 验证，不能把网页校验宣称为全机强制规则。
- 数据目录为 `/data/<用户名>` 形式，初始化指定实际根路径。目录用量与文件系统空闲空间分别展示。后台统计带采样时间，不跟随链接、不跨越未授权挂载、不在每次 GPU 扫描全量遍历目录。
- 不提供用户磁盘配额管理：删除空间/inode软硬限额、宽限期、配额接口与后台原生调用。容量告警仅提醒，不阻止写入，不清理文件。
- 个人目录用量及文件系统空闲空间配置告警阈值，默认 80% 提醒、90% 严重；第一版提醒为页面和事件日志，不自动删文件或终止训练。软删除账号仍计入存储用量；恢复账号不清零统计。
- 登录日志采集支持日志轮转、重启恢复、去重、时间/IP/用户名/结果筛选；未知用户名失败记录不错误关联到现有账号。只展示可确认的事实，缺失历史显示“无覆盖”，不推断没有登录；不收集密码或私钥。
- 共享目录示例为 `/data/shared/<项目名>`，其中 `shared` 为受管根保留名称，不能用作新用户名。root 拥有目录，普通用户通过独立系统组获得只读或读写权限，使用 setgid/default ACL 配置允许范围内的新文件继承。用户个人目录继续保持默认 0700。
- 共享授权/撤销、目录权限变更均需预览和审计；不移动或自动删除已有文件。移除组成员不撤销旧进程已持有的组身份或打开的文件句柄，页面提示重新登录及残留访问风险；不自动结束会话。已有文件权限迁移是单独的、明确范围的操作，不默认递归修改目录外文件。

### 10. 管理操作与运行就绪要求（2026-10-15）

- 维护账号默认仅用于运维，账号和任务保护均保留；训练使用普通人员账号，不拆分维护账号保护范围。
- 全局清楚显示真实服务器可写/只读/不可用状态。操作按钮说明具体限制原因，服务器仍独立核验每次操作。
- 账号、组和共享变更预览必须展示实际修改内容、目标身份与目录/访问影响。进程表仅用于进程操作；空进程范围不能掩盖其他操作的变更内容。
- 新建账号持久化非敏感执行进度，部分失败保持限制并展示待恢复状态；恢复仅续做属于该创建请求的步骤，核验账号、目录与设备身份并保留文件。凭据不得写入检查点或审计，恢复需要重新提供凭据。
- 账号详情结构化展示实际登录策略、有效期生效时刻、各项限制的原因和时间、最近确认登录、存储用量与活动覆盖。历史未保存的信息显示未知，不编造原因或时间。
- 中英文错误按稳定错误码提供说明和处理建议，原始技术诊断可展开。
- 已有账号可展示接管前置检查；本轮不处理旧账号目录迁移或权限统一。后续新账号目录都由经核验的初始化配置统一创建。
- 存储配置和验收属于本轮交付：核对实际设备/挂载，配置新账号的数据位置与团队共享；不自动格式化已有生产分区，不搬移老账号数据。
- 对密码/公钥、首次改密、交互 SSH、非交互 SSH 和 SFTP 使用独立测试账号验收。备份恢复和升级回滚先在隔离实例演练；实机重启与不存在的硬件组合不以模拟测试冒充验收。

### 2026-10-15 存储部署选择

当前测试服务器直接使用系统盘上的 `/data`，后续新账号采用 `/home/<用户名>` 与 `/data/<用户名>`；既有账号目录保持原位。用户已取消配额功能及对应维护窗口，保留目录隔离、用量统计和共享 ACL，不为此调整文件系统或重启服务器。

### 存储与共享专项体验

- 存储以文件系统容量卡片、结构化告警、个人及共享用量表展示；支持搜索、排序、账号生命周期筛选，默认未软删除账号，旧数据始终保留可查。采样未完成、数据过期和统计失败不伪装为零用量。
- 共享支持搜索、复制路径、查看当前主组/附属组成员和读写优先的权限解释；缺少权限组时引导管理员先创建组。配置成员不等同于已有会话或所有历史文件的有效权限。
- 共享列表应触发受锁保护的后台用量采样；创建失败仅可清理本次创建且身份相同的空目录，非空/身份变化必须保留。编辑权限失败标记需复核，完整ACL与默认继承回读通过后才报告授权成功。

### 2026-10-15：目录统计改为按需刷新

个人及共享目录不再自动递归扫描，也不再统计或展示文件数。磁盘容量与文件系统 inode 监控继续自动采集；策略项称为“磁盘容量采集周期”。管理员在存储页、共享目录页或账号目录信息页点击“刷新目录用量”，后台统计所有纳管账号及共享目录的字节用量。扫描期间禁止重复提交，显示统计状态、上次目录统计时间和失败提示。页面提示小文件较多时扫描可能耗时并增加磁盘 I/O。未统计的目录显示无数据，不用零值代替未知。

### 2026-10-15：共享目录按成员授权

管理员无需创建或选择 Linux 权限组。共享目录列表显示只读/读写成员数量，点击目录或“查看访问成员”查看用户及权限。编辑支持搜索纳管的正常人员账号、批量添加（默认只读）、逐人改为读写或移除；提交仍需预览并填写操作原因。读写包含创建、修改、删除，未授权成员不具有目录入口权限（系统管理员仍遵循 Linux 特权）。

每个目录的两类权限由平台专用组实现，绑定组 GID 和目录所有权，普通账号/权限组页面不能授予或修改这些内部组。预览绑定账号身份和原生成员状态；执行回读成员和 ACL。失败不显示成功，已有目录标记需重新核验，并尝试清空该目录的内部成员授权。

旧共享目录先按有效成员展示，只有修改成员后才启用专用授权；旧组及已有文件 ACL 保留，避免影响其他资源。新增成员访问旧文件可能仍需文件所有者授权；不自动递归覆盖历史文件权限。成员变化对新登录生效，已有会话可能继续保留访问能力。

### 2026-10-15：已登记旧共享目录兼容

已有共享目录按 root 端保存的原路径进行授权，不要求迁入新的共享根目录。必须核验安全父路径、root 所有权、目录身份及禁止符号链接；预览与执行之间身份变化即拒绝。新目录仍使用配置的共享根目录，客户端不能指定任意路径。

共享目录的“查看访问成员”及项目名打开只读弹窗，展示成员权限、路径和备注，不再展开列表行。弹窗与编辑界面采用统一宽度及滚动方式，支持关闭按钮、右上角关闭和Esc；授权修改仍从“编辑授权”入口进行。

### 2026-10-15：GPU 任务筛选与定位

默认范围继续为人员账号、全部进行中状态。筛选框显示值与请求状态同步；切换账号范围清空用户，任何筛选变化重置页码及勾选，支持重置为默认条件。空结果说明当前条件，可查看已结束任务或清除条件查看全部任务；加载失败单独展示错误与重试入口。

任务持久化曾使用的 GPU UUID，释放 GPU、主进程退出及任务结束后仍可按设备筛选。列表展示“使用过的 GPU”，悬停查看 UUID；该列表示历史关联，显存列表示当前占用。已结束任务不允许勾选合并或点击终止。旧记录若进程已清空且未保存设备信息，不推测其 GPU，只在“全部 GPU”下可见并明确提示。合并保留全部任务的设备历史，拆分新任务仅继承所选进程的设备。

### 2026-10-15：任务结束计时与systemd服务到期处理

任务记录最近确认存活时间和首次采集确认的结束时间。已结束任务运行时间冻结，剩余时间不再倒计时或显示负数，不标为进行中超时；历史记录缺少结束时间时显示无数据，不将升级时间当作实际结束时间。详情展示“结束时间（采集确认）”，这是采集观察时刻，包含采集周期误差。

PPID=1本身不代表残留worker。已核验leader identity匹配的人员服务主进程可以按已确认到期策略正常终止；未匹配的被收养进程仍遵循残留授权规则。非人员、维护/受保护账号、shell、PID1本身、白名单、UID、pidfd、策略版本和心跳限制保持有效。到期由采集/策略循环触发，当前5秒扫描存在数秒延迟，SIGTERM后按10秒宽限再复核是否需要SIGKILL；最大运行时间并非实时硬限时。

### 2026-10-17 组管理入口与成员操作

- 任务策略组与系统用户组分别展示。任务策略组只写平台配置，系统用户组使用原生组变更预览，不联动共享目录授权。
- 账号详情支持选择任务策略组；组详情支持搜索、多选添加成员（每批最多 200 人），或将成员移回默认组。
- 批量调整携带原分组，全部校验后事务提交；成员已被调整或账号变为只读时，整批拒绝，管理员重新选择。个人配置保留，已有任务保留策略快照。
- 系统用户组保留普通组管理、成员编辑、关键组和共享内部组保护。删除空组也需核对遗留文件的 GID 引用，平台不全盘扫描。
